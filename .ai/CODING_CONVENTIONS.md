
# 编码习惯与约定 (Coding Conventions)

## 目录与文件结构

项目采用“配置与演示分离”的模式。

- **规则配置**: 位于 `lib/` 目录下，按类别（`_extension.js`, `_fixable.js` 等）存放。
- **规则演示**: 位于 `demo/` 目录下，其子目录（`extension/`, `fixable/` 等）与 `lib` 中的配置文件一一对应。
- **文件命名**: 演示文件的名称应与它所演示的 ESLint 规则名完全一致，例如 `explicit-module-boundary-types` 规则的演示文件是 `explicit-module-boundary-types.ts`。


## 通用

### 文件格式规范（强制要求）

**文件头部和尾部空行要求（精确要求）：**
- **文件开头必须有且仅有一个空行**
- **文件结尾必须有且仅有一个空行**
- **违反此规定将导致代码审查失败**


## 演示示例的编码习惯和约定

### 核心原则
demo 文件的演示代码的目标都是为了清晰、独立地展示某一条 ESLint 规则的效果。
为此，需要创建一个“纯净”的测试环境，排除所有不相关规则的干扰。

- **最小化干扰**: 禁用其他可能干扰演示的规则
- **保留错误代码**: 作为教学示例，不修复错误
- 除了 demo 文件外，严格禁止修改任何现有文件（如 `.eslintrc.js`）
- 所有演示规则必须通过 demo 文件本身的 `eslint-disable` 注释来实现
- 提取干扰规则，将其禁用，只保留演示规则（过程中不要创建文件）
- 每个 demo 文件必须完全自包含，通过文件内注释禁用所有干扰规则
- 禁止通过外部配置影响 demo 文件行为
- 创建 demo 文件后必须运行验证命令，确认没有修改其他文件
- 验证命令示例：`git status --porcelain | grep -v "demo/"` 应该返回空


### 演示文件内容规范

#### 文件格式验证流程

在创建或修改 demo 文件后，必须执行以下验证步骤：

1. **规则验证**：运行 ESLint 检查，确保只触发目标规则
2. **文件隔离验证**：确保没有修改 demo 目录外的文件

#### 文件头注释

文件头必须遵循以下顺序和格式：

1.  **关闭 TypeScript 类型检查**:
    - 必须在文件第二行使用以下注释，以确保只关注 ESLint 的报错信息。
    ```typescript
    // @ts-nocheck: 关闭 TS 检查，只显示 ESLint 报错
    ```

2.  **禁用干扰的 ESLint 规则**:
    - 使用 `/* eslint-disable ... */` 来精确禁用任何可能与当前演示规则冲突的其他 ESLint 规则。
    - **禁止**使用宽泛的 `/* eslint-disable */`。
    ```typescript
    /* eslint-disable rule-name-1 */
    /* eslint-disable rule-name-2 */
    /* ... */
    /* eslint-disable rule-name-n */
    ```
3.  **添加必要的空行**:
    - **关闭 TypeScript 类型检查** 和 **禁用干扰的 ESLint 规则** 之间必须有一个空行。
    - 确保文件开头和结尾各有一个空行，符合文件格式规范。

#### 代码示例注释

- **正确示例**: 使用 `// ✓ 正确示例` 标记符合规则的正确代码。
- **错误示例**: 使用 `// ✗ 错误示例` 标记违反规则、预期会引发 ESLint 报错的错误代码。

#### 示例代码风格

- 代码示例应尽可能**简洁**，只保留与演示规则直接相关的最少代码。
- 每个示例都应清晰地展示规则在特定场景下的行为。

## 违规处理

### 文件格式违规（严格标准）
如果文件不符合"各一个空行"的精确要求：
1. **AI 智能体必须立即修复** - 在创建或修改文件时自动确保：
   - 文件开头有且仅有一个空行（不能多也不能少）
   - 文件结尾有且仅有一个空行（不能多也不能少）
   - 移除任何多余的连续空行

### 检查清单（精确标准）
创建或修改 demo 文件时，AI 智能体必须严格验证：
- [ ] 文件开头有且仅有一个空行（精确验证：第一个字符必须是 `\n`）
- [ ] 文件结尾有且仅有一个空行（精确验证：最后一个字符必须是 `\n`）
- [ ] 文件开头没有多个连续空行
- [ ] 文件结尾没有多个连续空行
- [ ] 只禁用干扰规则，保留目标规则
- [ ] 运行 ESLint 验证只触发目标规则
- [ ] 验证没有修改 demo 目录外的文件


*此文档旨在帮助协作者（包括 AI 智能体）快速理解并遵循项目固有的编码风格，以保持代码库的一致性。*
